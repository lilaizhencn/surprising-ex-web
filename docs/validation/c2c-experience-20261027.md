# C2C 交易体验验收 · 2026-10-27

本轮核对 Gateway 的 C2C Controller、QueryService、Views 与资金验证规则后完善用户界面，未修改后端或原生 Client 契约。

- 目录、收款账户、商家资料、质押、本人广告、订单分别接纳读取结果；失败的资料不能被当成真实空数据或用于对应操作。初始加载有状态，后台读取不反复卸载用户表单，慢请求未结束时不启动下一轮刷新。
- 广告按市场、方向、金额和收款方式取消过期查询；响应须与当前市场、方向和偏移相符。广告每页 20 条、订单每页 30 条；收款账户每页渲染 8 条，本人广告沿用服务端最近 100 条范围。
- 广告详情要求完整收款选项，出售默认选取该广告支持的本人已审核账户。报价须与账户、广告、收款账户和市场相符；按服务端有效时长与单调时钟计算截止，包含请求已耗时间。到期禁用确认，下单前再次查询有效性；金额与整数单位保留字符串。
- 下单和发布广告先持久化原 UUID、业务摘要与原正文，再发送写入；验证码单独发送，不进入本地原请求。回执严格核对所属账户、种类、原 key 与 hash；查询不重发，停止操作取消时不显示成功，也不改变原请求。损坏或不可读的本地记录明确阻止新建，恢复存储后可主动重读。
- 订单详情按精确订单 ID 独立读取，即使该订单不在当前列表页也能恢复。收款资料是本单快照，失败后隐藏未能确认的操作，要求重读原订单并重新核对到账、填写验证。付款窗口结束单独提示，终态仍取自服务端。
- 付款、取消、放币和申诉确认展示原订单、金额与数量。即时锁覆盖重复提交及重复确认；写入时锁定工作区与标签。放币需要勾选实际到账，验证码保持服务端账户/会话规则，允许已有有效验证凭据。已付款订单不再提供直接取消。
- 商家发布广告确认包含方向、价格、数量，原 payload 与收款账户不变；回执成功后仍按广告的 RESERVING 等实际状态显示。质押规则标记已配置时，版本、资产及正金额必须完整。
- 实名账户表单按后端姓名 2–80、账号 3–128、银行不超过 120 字符校验，方式要求银行时不得留空。完整提交响应通过核对后清空敏感输入；订单消息入口失败显示可重试的消息提示。
- 使用平台线性图标、语义按钮、间距、主题和减少动画规则；交易字段集与会话布局使用独立类名。确认交易定位焦点，订单返回恢复列表焦点，长标识与条款可换行。

未测范围：全部账户、报价、收款资料、验证码、广告和订单为显式合成数据；未登录真实商户、转账、划扣托管、放币或处理真实申诉。商户申请/退押、全部广告编辑分支、访客入口、完整聊天与附件、真实断网重连及服务端恢复未重新全量验收；历史联调资料继续保留，本轮不替代其真实资金证据。只有订单/广告原请求执行原有持久恢复机制，其他设置写入结果需按提示刷新核对。DOM、监听器、堆与主线程任务时间仅描述本机短时观察，不代表生产 CPU、长期无泄漏或性能提升。全站目标继续推进。
